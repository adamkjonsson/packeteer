# packeteer protocol

```
packeteer protocol check   <spec.yaml> [--strict]
packeteer protocol show    <spec.yaml> [--no-docs]
packeteer protocol compile <spec.yaml> [--out FILE] [--strict]
```

Works with **protocol specs**: YAML descriptions of an application protocol
that compile to a Python module packeteer treats exactly like a built-in.  See
{doc}`../protocols/index` for the language and {doc}`../protocols/format` for
the reference.

This is the only subcommand that does not read or write packets.  It turns a
spec into the module the other subcommands load with `--load-protocol`.

## `check`

Validates a spec and types every expression in it, before any data exists.
**Every fault is reported, not just the first.**

```console
$ packeteer protocol check sensor.yaml
sensor 1.0: ok
```

A spec with errors names each one with its file, line and path into the
document, and exits `1`:

```console
$ packeteer protocol check bad.yaml
error: bad.yaml:11: units.msg.fields[1]: unit 'msg' has no field 'nope'
bad 1.0: 1 error(s)
$ echo $?
1
```

| Argument | Description |
|----------|-------------|
| `FILE` | *(required)* Path to a `.yaml` protocol spec |
| `--strict` | Fail on warnings as well as errors |

`--strict` is the flag for CI: a warning is something the compiler can work
around but you probably did not mean.

## `show`

Prints the field tree a spec describes, expanding nested units in place.

```console
$ packeteer protocol show sensor.yaml
sensor 1.0 — input: datagram, over: udp, ports: 9000, entry: reading

enum kind: 0=temperature, 1=humidity, 2=pressure

reading
  One datagram — a header and a run of samples.
├── magic: u16 = 0x5345
├── version: u8
├── count: u8  (derived: count_of samples)
└── samples: → sample  ×count
    ├── kind: u8 enum kind
    ├── length: u8  (derived: size_of value)
    ├── value: bytes[length]  [sensitive]
    └── reading: i32 le
```

Derived fields, constants, enums and
[`sensitive`](sensitive) annotations are all shown, so the tree says what the
spec *means* rather than repeating what it says.

| Argument | Description |
|----------|-------------|
| `FILE` | *(required)* Path to a `.yaml` protocol spec |
| `--no-docs` | Omit each field's doc text |

**It works on a spec that does not yet check**, which is when it is most
useful — an expression that names a field that does not exist still appears in
the tree, so you can see what you wrote next to what you meant.

## `compile`

Compiles a spec to a Python module that registers an
{class}`~packeteer.protocols.AppProtocol`.

```console
$ packeteer protocol compile sensor.yaml
Wrote sensor.py (sensor 1.0, packeteer 0.12.0)
```

| Argument | Description |
|----------|-------------|
| `FILE` | *(required)* Path to a `.yaml` protocol spec |
| `--out FILE` / `-o FILE` | Where to write the module (default: beside the spec) |
| `--strict` | Refuse to compile a spec with warnings |

**The spec is checked first**, and a spec with errors is not compiled — the
same output as `check`, and exit `1`.  The generated module is also *imported*
before it is written, so one that cannot load is caught here rather than by
whoever runs it next.

The module is a plain Python file with no packeteer-specific loader:

```python
# Generated by packeteer 0.12.0 from sensor.yaml (spec sensor 1.0).
# Do not edit; edit the spec and recompile.
"""Field telemetry from the shed sensors."""
...
PROTOCOL = AppProtocol(
    name='sensor', over='udp', ports=frozenset({9000}),
    messages=(Reading,),
    decode=decode, encode=encode,
    to_spec=to_spec, from_spec=from_spec, sanitise=sanitise,
)

register(PROTOCOL)
```

Check it in, or regenerate it in a build step — either works.  It is meant to
be read: if packeteer decodes your protocol wrongly, the module is where you
find out why.

## Using the module

Registration is a side effect of importing, so something has to import it.
Every other subcommand takes `--load-protocol`:

```console
$ packeteer parse --load-protocol ./sensor.py capture.pcap
```

`packeteer parse --load-protocol … -o spec.json` writes a `"protocols"` key
into the spec, so `packeteer build spec.json` reloads the module without being
told again.  See [`packeteer parse`](parse) for the other two routes.

From Python, `import sensor` is enough, or
{func}`packeteer.protocols.load_module` when you have a path rather than an
import name.

```{tip}
Once, while the spec is fresh, hold the compiled protocol to the contract
every protocol must meet:

    from packeteer import conformance, protocols

    failures = conformance.check_protocol(
        protocols.for_section("sensor"), [a_sample_message],
    )
    assert not failures, "\n".join(failures)

{func}`~packeteer.conformance.check_protocol` found two defects in packeteer's
own shipped code the first time it was run, one of them in an example spec.
```
