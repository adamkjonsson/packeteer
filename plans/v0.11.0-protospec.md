## The constraint that shapes this milestone

**Two constraints, and the second one is new.**

**kober is decode-only; packeteer cannot be.** The compiler emits an encoder
as well as a decoder, because `parse` → edit → `build` is what packeteer is
for. That brings two problems a decoder never has: derived fields must be
*computed* rather than read, and a capture whose derived field disagrees with
the bytes beside it must still rebuild byte-for-byte. The
[derived-field rule](#the-derived-field-rule) is the whole answer, and it is
the single most important thing in this plan.

**Length-prefixed stream framing brings TCP reassembly into packeteer**
([Q6](user-defined-protocols.md#q6)). packeteer has nothing like it today
outside {class}`~packeteer.parse.defragment.Defragmenter` for IP fragments.
This is roughly a quarter of the milestone, it is the part with no existing
code to imitate closely, and it forces an entry-point split that the docs have
to carry — see [Part 4](#part-4--framing-and-reassembly).

Everything here produces something the v0.10.0 contract already accepts, with
**one addition to that contract**: `AppProtocol` gains an optional
`frame_length` callable, which is how a stream-framed protocol tells the
reassembler where a message ends. It is defaulted, so nothing breaks.

# Part 1 — the language

## Relationship to kober's dialect

Settled in [Q3](user-defined-protocols.md#q3): **a superset**. kober's keys
keep kober's meaning, and packeteer adds five of its own. A kober spec loads
and decodes; adding `derive:` lines makes it bidirectional.

Two axes are easy to confuse and must not be:

| Key | Axis | Values |
|---|---|---|
| `input` | *(kober's)* the stream shape the spec is written against | `datagram`, `stream`, `either` |
| `over` | *(packeteer's)* which transport carries it | `udp`, `tcp`, `either` |

A spec declares both. They are independent: DNS is `input: datagram, over:
udp` over UDP and `input: stream, over: tcp` over TCP, which is exactly why
kober needed the distinction and why borrowing it is better than inventing a
third word.

`check` must report a kober construct this version does not implement as
**"not supported yet"**, naming it — never as "unknown key". The difference is
between *this will work later* and *you typed something wrong*, and a user
pasting in a kober spec will hit it on the first try.

### What #105 corrected

The grammar above was written from kober's docs and got four things wrong,
each found by loading kober's own `dns.yaml` and `http.yaml` rather than by
review:

| Assumed | Actually |
|---|---|
| `size: 4` or `size: "expr"` | a **tagged mapping** — `{fixed: 4}`, `{expr: "n"}`, `{remaining: true}`, `{terminated: {…}}`; a bare integer is the one shorthand |
| a switch's `arms:` | `cases:` |
| `{unit: name}` | also `{unit: {name: x, args: […]}}`, where `args` is kober's unit parameters |
| `on:` is a string key | `on:` is a **YAML 1.1 boolean**, so a switch's dispatch key arrives as `True` |

The plan's own example spec was invalid as printed, which is the argument for
keeping it as a real file: it now lives at `examples/protocols/sensor.yaml`
and the tests load it, so it cannot drift again.

Both kober specs now load and report exactly the constructs this plan
predicted: `dns` gives `pointer` and `unit.args`; `http` gives
`size.terminated`, `select`, `computed` and `repeat.until`.

### YAML's implicit typing, and why the resolver is left alone

YAML 1.1 reads `on`, `off`, `yes` and `no` as booleans and `1.10` as a number.
Swapping PyYAML's resolver for a YAML 1.2 one would remove the trap wholesale,
and was considered and rejected: **a spec has to mean the same thing to every
YAML tool that opens it.** Reinterpreting the document would make `signed: yes`
the string `"yes"` here and `True` in yamllint, an editor, or any other loader,
which is a bad trade for a language whose job is unambiguous description.
PyYAML also has no 1.2 mode, so doing it means overriding the bool, int, float
and null resolvers by hand, and a partial job invents a third dialect that is
neither 1.1 nor 1.2.

So the loader **names the coercion and says to quote it**, which is kober's
approach and deliberately kober's wording. The switch `on:` key is the one
narrow repair, because that coercion happens to a *key* — no error message can
reach a key you never see.

Two bugs this turned up in #105, both now fixed: `version` was `str()`-coerced,
so `version: 1.10` silently became `"1.1"`; and a unit or enum name YAML turned
into a bool became the string `"True"`, registering a unit under a name nobody
wrote.

The compatibility claim is documented and reasoned, **not enforced in CI**
(the fixture-vendoring option was declined in Q3 because the copies drift).
Worth knowing when it is eventually wrong.

## The five keys that are packeteer's

```yaml
name: sensor
version: "1.0"
input: datagram            # kober's key, kober's meaning
entry: reading
over: udp                  # packeteer
ports: [9000]              # packeteer
doc: Field telemetry from the shed sensors.

enums:
  kind: {0: temperature, 1: humidity, 2: pressure}

units:
  reading:
    fields:
      - {name: magic,   type: {int: {bits: 16}}, const: 0x5345}   # packeteer
      - {name: version, type: {int: {bits: 8}}}
      - {name: count,   type: {int: {bits: 8}},
         derive: {count_of: samples}}                             # packeteer
      - {name: samples, type: {unit: sample}, repeat: {count: count}}

  sample:
    fields:
      - {name: kind,   type: {int: {bits: 8, enum: kind}}}
      - {name: length, type: {int: {bits: 8}}, derive: {size_of: value}}
      - {name: value,  type: {bytes: {size: {expr: "length"}}}, sensitive: true}  # packeteer
```

- **`over:` / `ports:`** — the binding that makes decoding automatic, and what
  the generated `AppProtocol` is built from. Without them a compiled protocol
  would have to be wired up by hand, which is the thing v0.10.0 exists to
  avoid.
- **`const:`** — encode writes it, decode **checks** it and raises on
  mismatch. This is the "does this payload actually belong to me" test, and it
  matters precisely because a port claim is weak: the raise is what makes
  `_try_parse_app` leave someone else's bytes as an opaque payload. The
  guide written in #103 already tells authors to check a magic number; this is
  how a spec says it.
- **`derive:`** — the encode-direction answer, `size_of:` and `count_of:` in
  v1.
- **`sensitive:`** — consumed in v0.12.0, but in the grammar from the start so
  specs written now do not need revisiting.

## The derived-field rule

For every field carrying `derive:`, generated code does exactly this:

- **encode** — write the derived value, *unless* the object carries an
  explicit override, in which case write the override. The dataclass field is
  therefore `int | None = None`, where `None` means "derive it".
- **decode** — read the value. If it equals what the derivation would produce,
  set the attribute to `None`; if it differs, keep the captured value.
- **`to_spec`** — omit the key when the attribute is `None`.

The consequence is the property the whole feature stands on. A well-formed
capture produces a *clean* spec with no redundant length and count keys, and a
**malformed** capture — a length field that lies — produces a spec that
records the lie and rebuilds it byte-for-byte.

This is not a new idea in packeteer; it is the rule `transport.length` and
`transport.checksum` have followed since 0.9.0
(`_clear_derivable_transport_fields`), and that 0.9.1 had to fix for truncated
captures. **Applied by a compiler instead of by hand, for every derived field
in every spec.** Reading the #68/#92 history before implementing it is
time well spent: those two issues are what this rule looks like when it goes
wrong.

## The subset

| In | Out — and why |
|---|---|
| `int`, 1–64 bits, signed/unsigned, either endianness, optional enum | **compression pointers** — decode is kober's `pointer:`, but *encoding* one needs a compression model; packeteer's own DNS encoder declines to compress |
| `bytes` / `string`, fixed size or sized by an earlier field | **delimiter framing** (`until b"\r\n\r\n"`) — the text-protocol path |
| `unit`, nested, no recursion | **`select`** — a question asked across a repeated field; HTTP's framing needs it |
| `repeat: {count: <field>}` | **checksum derivations** — needs an algorithm table and a coverage expression |
| `switch` on an earlier field; no default → the region stays `payload` | **recursion**, `params:`, `to_end` repeats |
| `const:`, `derive:`, `sensitive:` | |

The honesty test: **DNS-over-TCP becomes expressible; DNS-over-UDP does not**
(compression pointers) **and HTTP does not** (delimiter framing, `select`).
The built-ins stay hand-written, as they will for the foreseeable future.

DNS-over-TCP being expressible is worth exploiting: it is the one case where a
generated protocol can be diffed against a hand-written one that is already
tested. See [the conformance idea](#the-dns-over-tcp-conformance-check).

# Part 2 — the checker

`check` validates a spec and types every expression in it **before any data
exists**. It reports every fault it can find rather than stopping at the
first, which is what lets a spec be fixed in one pass — kober demonstrates
this and it is worth copying exactly.

## What it inherits from kober

A field may only reference fields decoded before it; unknown enum names;
unreachable units; a `repeat` count that is not an integer expression;
type errors in expressions.

## What is new, because packeteer encodes

The bidirectional obligation. `check` must refuse **specs that decode but
cannot encode**:

- a `derive:` naming a field it does not actually size or count;
- a `size_of:` on a field whose encoded length is not determined by the object
  (for example a `switch` whose arms differ in length and whose selector is
  itself derived from the switched region);
- a `bytes` field sized by an expression that cannot be inverted;
- `const:` on a field the encoder cannot place, such as one inside a
  conditional whose condition depends on it.

## What is new, because of streams

For `input: stream`, `check` must prove the entry unit is **length-prefixed**:
the framing length is readable from a fixed-position prefix, meaning no
variable-length field precedes it. It computes the minimum prefix size and
records it, because the compiler needs that number to generate
`frame_length` and the reassembler needs it to know how many bytes to wait for
before it can know anything.

A stream spec that fails this is refused with *not supported yet*, naming the
field that made the prefix variable. That message is the one a user is most
likely to see, so it is worth writing carefully.

# Part 3 — the compiler

## The generated module

```python
# Generated by packeteer 0.11.0 from sensor.yaml (spec sensor 1.0).
# Do not edit; edit the spec and recompile.
from __future__ import annotations
...

@dataclass
class Sample:
    kind:   int = 0
    length: int | None = None       # derived: size_of(value)
    value:  bytes = b""

@dataclass
class Reading:
    magic:   int = 0x5345           # const
    version: int = 0
    count:   int | None = None      # derived: count_of(samples)
    samples: list[Sample] = field(default_factory=list)

def encode(msg: Reading, transport: str = "udp") -> bytes: ...
def decode(data: bytes, transport: str = "udp") -> Reading: ...
def to_spec(msg: Reading) -> dict[str, Any]: ...
def from_spec(section: dict[str, Any]) -> Reading: ...
def frame_length(prefix: bytes) -> int | None: ...   # input: stream only

PROTOCOL = AppProtocol(name="sensor", over="udp", ports=frozenset({9000}), ...)
register(PROTOCOL)
```

Import it and everything from v0.10.0 works: `PacketBuilder().app(Reading(...))`,
`pkt.app`, a `"sensor"` section in the spec, `packeteer build` reading it back.

## Safety of generated code

Three rules, taken from kober's `pygen.py` because the failure mode —
author-supplied text reaching Python source — is severe:

1. **Names are validated against a whitelist, never silently renamed.** A spec
   field that is not a Python identifier, is a keyword, or collides with a
   generated name is a `CompileError`. A decoder whose field quietly changed
   name is worse than one that will not compile.
2. **Nothing is interpolated.** `doc:` strings and enum labels become escaped
   literals and escaped docstrings.
3. **`codegen` runs `ast.parse` on its own output before writing it**, so a
   generator bug is a refusal rather than a broken module on someone's disk.

## Output path

Settled in [Q7](user-defined-protocols.md#q7): `--out` is optional and
defaults to `sensor.py` beside `sensor.yaml`. The generated file is meant to
be committed and reviewed, so it lands where the author is already looking.
The header names the spec and the packeteer version that produced it.

## Dependencies

packeteer has **zero runtime dependencies** and keeps them. JSON specs work
from the stdlib; YAML is an optional extra (`packeteer[yaml]`), needed only to
*compile*. A generated module imports nothing but `packeteer` and the stdlib —
which is worth a test, since it is the property that makes a compiled protocol
safe to vendor.

# Part 4 — framing and reassembly

The part with no close precedent. Settled in
[Q6](user-defined-protocols.md#q6), [Q8](user-defined-protocols.md#q8) and
[Q9](user-defined-protocols.md#q9).

## The contract extension

`AppProtocol` gains one optional field:

```python
frame_length: Callable[[bytes], int | None] | None = None
```

Given the bytes of a flow so far, it returns the total length of the message
at the front, or `None` when there is not yet enough to tell. `None` on the
*field* means the protocol is datagram-framed and needs no reassembly. This is
the only change to the v0.10.0 contract, it is defaulted, and it is the whole
interface between a compiled protocol and the reassembler.

## The `Reassembler`

Shaped like {class}`~packeteer.parse.defragment.Defragmenter`, because that is
the shape this codebase already teaches:

```python
@dataclass
class ReassembledMessage:
    data:   bytes            # one whole message
    flow:   FlowKey          # (src, dst, src_port, dst_port)
    tokens: list[Any]        # records that carried it, in arrival order

@dataclass
class IncompleteMessage:
    flow:           FlowKey
    bytes_seen:     int
    expected_bytes: int | None
    reason:         str      # "timeout" | "gap" | "capped" | "eof"
    tokens:         list[Any]

class Reassembler:
    def feed(self, pkt: ParsedPacket, token: Any = None) -> list[ReassembledMessage]: ...
    def flush(self) -> None: ...
    incomplete: list[IncompleteMessage]
```

`IncompleteDatagram.reason` is the precedent for `reason`, and it earns its
place for the same purpose: a consumer reporting what it could not read wants
to name why.

## Sequence-aware, and why

Settled in [Q8](user-defined-protocols.md#q8). Bytes are placed by TCP
sequence number, not arrival order:

- **retransmission** — bytes covering an already-seen range are dropped;
- **overlap** — only the new part is taken;
- **gap** — held, and if it is still missing when the flow times out, the
  message is abandoned with `reason="gap"` rather than spliced into something
  corrupt;
- **SYN** consumes a sequence number, which is the classic off-by-one.

The concrete reason this is not optional: `packeteer stream` with
{class}`~packeteer.generate.impairments.ImpairmentOptions` **deliberately
emits spurious retransmissions and leaves permanent gaps** where a segment was
lost. An arrival-order reader would mis-decode packeteer's own generated
corpus, which is the first thing anyone would test a new spec against.

Bounds, following `Defragmenter`: a per-flow byte cap, a flow count cap, and a
timeout, each abandoning with a distinct `reason`. A reassembler without
bounds is a memory-exhaustion bug waiting for a crafted capture.

## Where it plugs in, and where it must not

Settled in [Q9](user-defined-protocols.md#q9), and it is #73's split reached
for #73's reason:

| Entry point | Reassembly | Why |
|---|---|---|
| `iter_packets` | **on** by default | The analysis front door — "give me messages, not segments" |
| `parse_pcap_file` / `packeteer parse` | **off**, opt-in | **The spec path is the round-trip path.** A capture whose messages were reassembled rebuilds as whole messages rather than as the segments that carried them, and stops round-tripping |
| `parse_packet` | n/a | One packet, no flow state — it cannot reassemble, exactly as it cannot defragment |

`PacketReader` grows an `incomplete_messages` list beside its existing
`incomplete`, kept separate because abandoning a datagram and abandoning a
message are different events with different causes.

## Which packet carries the message

The one that **completes** it. Its `app` is set and its `payload` cleared, as
`_try_parse_app` already does on success; earlier segments keep their own
partial payloads and have `app is None`. `source_records` on the completing
packet spans every contributing record, mirroring `AssembledFrame.tokens`.

For the common case — one message per segment — this is a no-op and behaviour
is exactly what 0.10.0 does today. That is worth a test in its own right, so
that adding reassembly does not quietly change DNS-over-TCP.

## The DNS-over-TCP conformance check

DNS-over-TCP is the first protocol expressible in the subset that packeteer
*already implements by hand*. A spec for it, compiled and run against the same
captures as `packeteer.app.dns`, is the strongest available evidence that the
compiler produces correct decoders — much stronger than any toy protocol.

Worth doing even though the generated version will not replace the built-in:
DNS-over-UDP needs compression pointers, so the two cannot merge. Treat it as
a test fixture, not a migration.

# Part 5 — the CLI

## Tests

- **Round-trip properties per spec, over random messages:**
  `decode(encode(m)) == m` and `encode(decode(b)) == b`. The second is the one
  that catches derived-field bugs.
- **The lying-length capture** — a payload whose length field disagrees with
  its data: decode records it, `to_spec` emits it, `from_spec` → `encode`
  reproduces the original bytes exactly. This is #68's test, generated.
- **`const` mismatch** → `ValueError` → the packet keeps its `payload` section
  through `packeteer parse`.
- **`check` refuses** each documented fault class, reporting all of them in
  one pass, with the spec's line number.
- **`codegen` refuses** every hostile name: keywords, non-identifiers,
  collisions, and a `doc:` containing `"""`.
- **A generated module imports only `packeteer` and the stdlib** — asserted
  by walking its AST, the way `test_protocols.py` already does for
  `protocols.py`.
- **The reassembler** against synthetic sequences: in order, reversed,
  duplicated, overlapping, with a gap, with a SYN, and past every bound.
- **The reassembler against `packeteer stream --payload …` with impairments
  on**, which is the corpus that motivated Q8.
- **One message per segment is a no-op**, so DNS-over-TCP behaves exactly as
  it does in 0.10.0.
- Truncated input at every byte offset of a valid message raises cleanly
  rather than returning a half-built object.

## Undecided

<a id="qa"></a>
**QA — Does `packeteer parse` get a `--reassemble` flag?** [Q9](user-defined-protocols.md#q9)
settles that reassembly is *off* there. Whether it is available at all is
separate. `--defragment` exists as the precedent, and the same reasoning
applies: someone analysing rather than round-tripping wants it.
*Recommendation: yes, `--reassemble`, documented as breaking byte-exact
rebuild*, exactly as `--defragment` is.

<a id="qb"></a>
**QB — Does a generated module carry its spec?** Embedding the spec source as
a string constant makes a compiled module self-describing and lets a future
`packeteer protocol show sensor.py` work without the YAML. It also doubles the
file size for large specs and creates a second copy that can disagree with the
first.
*Recommendation: embed a hash, not the source.* Enough to detect that a module
is stale against its spec, without carrying a duplicate.

<a id="qc"></a>
**QC — What happens when a compiled module is older than the packeteer running
it?** The generated header names the version. Refusing to import across a
major version is safe but brittle; ignoring it entirely means a silent
mismatch when the runtime contract changes.
*Recommendation: warn, do not refuse*, and add the check to the conformance
suite in v0.12.0 so the promise is tested rather than asserted.

## Cross-cutting

- **Version.** `pyproject.toml` is at `0.11.0.dev0` since #105.

- **JSON object keys are always strings.** `{"1": …}` and YAML's `{1: …}` must
  name the same key — true for switch cases and, as #105's tests found, for
  enum values too. Both go through one helper. Anything else keyed by number
  that gets added later needs the same treatment.

- **The v0.10.0 contract gains one field.** `AppProtocol.frame_length`,
  optional and defaulted, so no `Breaking:` marker. It is the only change to
  what v0.10.0 shipped, and everything else here is additive.

- **kober.** Do not vendor it and do not depend on it — more than half of it
  is zipline's citation and coverage model, which packeteer has no use for.
  What transfers is the design, and largely the text, of `spec.py`,
  `check.py`, `expr.py`, `loader.py` and `errors.py` — about 3,100 of its
  10,500 lines. `pygen.py` is the right template for *emitting safe Python*
  and the wrong output shape. Same author, so licensing is not the question;
  release cadence is.

- **Ruff.** `codegen.py` will strain `max-statements = 200` and
  `max-branches = 20`. Split the emitters per construct rather than raising
  the limits — CLAUDE.md forbids relaxing `ruff.toml` to silence a warning.
